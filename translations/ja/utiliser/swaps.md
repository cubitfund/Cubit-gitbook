# 購入と売却

dapp は選択したデプロイのルーターで ETH/CUBIT スワップを提供します。税はフックで適用され、受取見込額は見積もりに含まれる税を控除済みである必要があります。

> Ethereum に接続された dapp は **LP 手数料 0.01 %** の現行バージョンを使用しており、そのバージョンの ABI を読んでいます。市場が開くまで取引はできません。デモやシミュレーションモードはオンチェーン状態ではありません。

## スワップの準備前に

ウォレットのネットワーク、表示デプロイ、データのブロックを確認し、交換額に加え gas 用 ETH を確保します。dapp は RPC 障害や古いデータを通知し、未検証状態に基づく署名を防ぐ必要があります。

アカウント、ネットワーク、金額、ルーターアドレスが変われば再見積もりが必要です。周辺アドレスは V2 レジストリで変更されます。

## CUBIT を購入する

1. ETH 額を選びます。exact-input では購入税 3 % が含まれます。
2. CUBIT の手取り見込量、手数料、スリッページ許容度で定めた最低受取量を確認します。
3. シミュレーションとウォレットの詳細を確認し、署名します。
4. 成功レシートとオンチェーン残高の更新を待ちます。

購入は `msg.value` でネイティブ ETH を使用します。この CUBIT ルーター経路で Permit2 は使いません。新バージョンでは、購入はバンドの x·y=k 曲線に従ってバンドから CUBIT を取り出します。

## CUBIT を売却する

売却には、選んだ数量の CUBIT をルーターが送金できる **ERC-20 承認（approval）**が必要な場合があります。フロントエンドは要求数量分の承認を準備します。

承認後、dapp はスワップ前にアカウント、ネットワーク、レジストリ改訂番号、見積もりの鮮度を再確認します。承認量不足時は承認と売却が別々の取引になります。

売却は税 15 % 控除後の ETH を返します。総 ETH の 12 % は買い壁の資金に、3 % はチーム分になります。新バージョンでは、売却は完全に通過した買い壁を空にし、待機中の ETH を買い壁に配置します。その後、CUBIT ルーターが吸収された CUBIT を Vault の準備金へ送ります。

## 最低受取量と期限

**スリッページ**は見積もりに対する許容差を制限します。税が見積もりに含まれることは、許容度に任意に 15 ポイント加える理由になりません。

確認したフロントエンドでは見積もりは **30 秒**有効です。取引期限はチェーンの timestamp から計算します。承認待ちが長いと署名が防止され、新しい見積もりの確認が必要になります。

制限による拒否は合意した最小・最大額を保護します。失敗しても制限をなくすべきとは限りません。

## 取引が通らない場合

| 状況 | 有効な対応 |
| --- | --- |
| ネットワーク違い・アカウント変更 | 目的の状態に戻して再見積もり |
| 見積もり期限切れ | 手取り額と最低受取量を再計算 |
| ルーター・改訂番号変更 | 現在のアドレスと新操作を確認。旧承認は旧 spender に残る |
| 流動性不足 | 少額での見積もりと既存ポジションを確認 |
| 非常に多くの買い壁を通過する売却 | 売却を分割。通過する買い壁が約 88 を超えると 1 取引の gas 上限を超える |
| RPC 障害 | 有効なオンチェーン読取りを待って署名 |
| 送信済み取引 | 次の準備前に hash とレシートを確認 |

ルーターは全量消費されない入力や満額提供できない exact-output を拒否します。巻戻し取引の支出は gas を除き EVM が取り消します。

## 結果を確認する

hash は提出を示し、成功はレシートで判断します。エクスプローラーのネットワーク、状態、受取人、`BuyTaxed` または `SellTaxed` イベントを確認します。

買い壁の参照価格は個別注文の見積もりを代替しません。[dapp データを読む](preuves.md)。
