# dapp のデータを読む

Proof ページでは表示値をプロトコルの状態やイベントと照合します。金額の解釈前に**ネットワーク、デプロイ、バージョン、読取りブロック**を確認します。

> 公開 dapp は稼働中の Ethereum デプロイとその ABI を読んでいます。以下のデータは、画面が区別すべき内容を説明するものです。

## 区別すべき数値

| データ | 示すもの |
| --- | --- |
| 市場価格 | プールの現在価格。特定数量の手取り結果とは異なる |
| バンドの ETH | 現在価格でバンドが実際に保有する ETH。購入者が持ち込んだもの |
| バンドの CUBIT | バンドがまだ購入向けに提供している CUBIT |
| 次の買い壁の目標 | 現在価格で計算した水準。資金供給されたポジションとは別 |
| 有効買い壁 | 資金供給済みのポジション。それぞれ ID、tick、残りの流動性を持つ |
| 待機 ETH | 配置されずに残った買い壁の資金：ポジションを作るには小さすぎる端数、または tick 範囲の最上端にある価格 |
| 送付待ちの CUBIT | 通過された買い壁の CUBIT。Vault へ送られるまでフック内に分離して保持 |
| 報酬準備金 | 預入者への支払いのために Vault が保有する CUBIT。預入れとは別 |
| 流通供給量 | 総供給量から、買い壁の CUBIT、送付待ちの CUBIT、各 Vault の報酬準備金を差し引いた量。Vault に預け入れた CUBIT は流通に含まれる |

買い壁の水準と残りの ETH は併せて確認します。バンドの ETH と買い壁の ETH は、二つの独立したブックに属します。

## 新バージョンで変わること

旧ビューはラダー、クッション、バーンキュー、メンテナンス画面を表示していました。新バージョンでは、これらが単一のバンド、売却ごとに配置され空にされる買い壁、Vault 内の報酬準備金に置き換わります。Keepers ページはもうありません。

従来の名前 `floorPrice` は最後に資金供給された買い壁を示すもので、市場全体の最低価格と読んではいけません。価格が下がったときは、新しい買い壁が前の買い壁より低く置かれることがあります。

新しいフィールドは[連携](../developper/integration.md)で詳しく説明しています。Ethereum に接続された dapp は現行バージョンのフィールドを読んでいます。

## 控除前価格、手取り価格、見積もり

控除前の参照値はポジションの価格水準です。手取りの参照値には範囲端、LP 手数料、売却税、v4 プロトコル手数料の仮定を含む場合があります。

実際の売却は数量、通過ポジション、丸め、gas に依存します。「net floor」はウォレットの損益計算ではなく、見積もりを代替しません。

## データのモード

| 表示 | 解釈 |
| --- | --- |
| オンチェーン、ブロック特定済み | 指定デプロイから読んだデータ |
| 読込み中 | 初回読取りが未完了 |
| 古いデータ・RPC 障害 | 最終既知状態。署名を許可する根拠ではない |
| シミュレーション・デモ | 仕組みのローカル例 |

将来のリリースでは、公表された提供状況と利用者向けモジュールのアドレスを確認してください。

## 再確認する

トークン、フック、プールの識別情報を確認し、現行レジストリモジュールと `moduleRevision` を調べます。イベントを取引 hash と正規ブロックに照合します。

Proof ページで税と買い壁を追跡できます。スクリーンショットや旧報告は版の特定を代替しません。[バージョンの実際の状況](../securite/etat.md)。
