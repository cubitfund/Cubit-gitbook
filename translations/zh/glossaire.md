# 术语表

| 术语 | CUBIT 中的定义 |
| --- | --- |
| ABI | 与合约通信所需的函数、事件和类型描述 |
| 部署者买入 | 包含在启动交易中的 0.1 ETH 买入，征收 3 % 的税，所得代币不锁定 |
| 团队地址 | 固定的地址，获得税费中的团队份额，并可随时、无需等待地替换注册表中的模块，随后将其激活；其权力是永久的 |
| Approval（授权） | 给 spender 地址指定金额的 ERC-20 许可 |
| 流动性带 | 启动时以 80 % 的供应量建立的唯一交易仓位，覆盖高于启动价格的全部价格，永不撤出 |
| Burn（销毁） | 销毁代币；新版本不再销毁买墙中的 CUBIT，只销毁启动时的舍入零头 |
| 目标 | 每笔卖出时按卖出后的价格为配置买墙计算的价位：0.4 × 当前价格 + 0.6 × 启动价格；价格等于或低于启动价格时，买墙配置在现价下方 1 % |
| ERC-6909 claim | 在 PoolManager 持有、用于结算或保存资产的记账单位 |
| 奖励 claim | 领取已获得奖励的调用，与 ERC-6909 claim 含义不同 |
| x·y=k 曲线 | 流动性带中买入和卖出所遵循的恒定乘积曲线 |
| 持有 CUBIT | 流通供应量减去流动性带尚未卖出的 CUBIT：持有者手中的数量，含已质押的 CUBIT |
| Deadline（期限） | 操作或签名可接受的最大时间戳 |
| Exact-input | 输入固定、输出受最小值保护的交换 |
| Exact-output | 输出固定、输入受最大值保护的交换 |
| 启动 FDV | 决定启动价格的完全稀释市值；新版本采用 3.75 ETH |
| LP 费用 | 池佣金，区别于 hook 税 |
| Floor | 代码中使用的历史名称；应分开读取买墙和目标 |
| Hook | 接入 Uniswap v4 操作的合约，在此执行 CUBIT 机制；它没有任何管理员 |
| Idle ETH（闲置 ETH） | 已记账但不在任何仓位中的 ETH，需注明分区 |
| Lens | 从 hook 和池推导数字的读取合约 |
| 流动性 / 深度 | 依状态与价格，仓位中实际可用的资产 |
| 最佳买墙 | 最接近市场的活跃买墙，即卖出最先遇到的买墙；Lens 提供其总价以及扣除费用和税后的净价 |
| 买墙 | 由卖出以 ETH 注资、位于固定 tick 的 LP 仓位；每个 tick 只有一个买墙 |
| 部分消耗的买墙 | 部分 ETH 已回购 CUBIT 的买墙；它保持原位 |
| 被穿越的买墙 | 被卖出完全转换为 CUBIT 的买墙；穿越它的那笔卖出将其清空，转入 vault 储备 |
| 流通供应量 | 总供应量减去买墙中的 CUBIT、等待发送的 CUBIT 以及所有已登记 vault 的奖励储备；已质押的 CUBIT 仍计入流通 |
| Pending absorbed tokens | 被穿越买墙中的 CUBIT，隔离在 hook 中，直至由 `deliverAbsorbed()` 发送 |
| Pending floor ETH | 等待配置的买墙资金：卖出的 12 % 及被穿越买墙释放的 ETH，由同一笔卖出配置；只有太小而无法形成仓位的零头，以及价格位于 tick 范围最顶端的极端情况，才会留在其中 |
| Permissionless（无需许可） | 人人可调用，受合约确定性条件限制 |
| PoolId | 从完整 PoolKey 推导的标识符 |
| 启动价格 | 部署时固定的每 CUBIT ETH 价格：启动 FDV 除以 2100 万 |
| V2 注册表 | 保存当前模块、修订、已开放功能及 vault 历史的合约 |
| 奖励储备 | vault 为支付存款人而持有的 CUBIT：启动时 20 % 的供应量，之后是被穿越买墙中的 CUBIT |
| Slippage（滑点） | 相对报价可接受的执行差，由交换限制约束 |
| Snapshot（快照） | 在指定区块读取的一致数据集 |
| Tick | 池价格离散单位，方向与 ETH/CUBIT 价格相反 |
| V1 / V2 | 市场核心 / 路线图附加功能 |
| 治理 vault | Launchpad 的 vault，接收 Forge 的启动费用（ETH，不退还给启动者）及 Forge 子项目买墙的代币；每笔存入锁定 30 天，另加可能的延长，之后只有其部署者可以领取，永久有效且这项权利无法转让；该部署者可以延长锁定，但绝不能缩短 |

单位与合约方法见[集成](developper/integration.md)。
