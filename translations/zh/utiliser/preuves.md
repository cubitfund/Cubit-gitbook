# 读取 dapp 数据

Proof 页面用于将显示数字与协议状态及事件对照。解释金额前先确认**网络、部署、版本和读取区块**。

> 公开 dapp 读取在用的 Ethereum 部署及其 ABI。下列数据描述界面必须区分的内容。

## 需要区分的数字

| 数据 | 描述内容 |
| --- | --- |
| 市场价格 | 池当前价格，不同于特定数量的净成交结果 |
| 流动性带中的 ETH | 流动性带按当前价格实际持有的 ETH，由买方带入 |
| 流动性带中的 CUBIT | 流动性带仍可供买入的 CUBIT |
| 下一个买墙的目标 | 按当前价格计算的价位，不同于已注资仓位 |
| 有效买墙 | 已注资仓位，各有 ID、tick 与剩余流动性 |
| 待配置 ETH | 未配置的买墙资金：太小而无法形成仓位的零头，或价格位于 tick 范围最顶端 |
| 待发送的 CUBIT | 被穿越买墙中的 CUBIT，隔离在 hook 中，直至发送到 vault |
| 奖励储备 | vault 为支付存款人而持有的 CUBIT，与存款分开 |
| 流通供应量 | 总供应量减去买墙中的 CUBIT、等待发送的 CUBIT 以及各 vault 的奖励储备；存入 vault 的 CUBIT 仍计入流通 |

买墙价位与其剩余 ETH 必须一起看。流动性带中的 ETH 与买墙中的 ETH 属于两本不同的流动性簿。

## 新版本带来的变化

旧视图展示阶梯流动性（ladder）、缓冲仓位（cushion）、销毁队列和维护画面。新版本以单一流动性带、每笔卖出时配置和清空的买墙以及 vault 中的奖励储备取而代之。不再有 Keepers 页面。

历史名称 `floorPrice` 表示最近一次获得注资的买墙：不应理解为全市场最低价。价格下跌后，新买墙可能配置在比前一个更低的位置。

新字段详见[集成](../developper/integration.md)。连接 Ethereum 的 dapp 读取的是当前版本的字段。

## 毛价、净价与报价

毛参考价表示仓位的价格水平。净参考价可纳入区间边界、LP 费用、卖出税和对 v4 协议费的假设。

实际卖出取决于数量、穿越仓位、舍入与 gas。“净 floor”参考不是钱包收益计算，也不替代报价。

## 数据模式

| 显示 | 解读 |
| --- | --- |
| 链上，有区块标识 | 从指定部署读取的数据 |
| 加载中 | 首次读取尚未完成 |
| 数据过期或 RPC 故障 | 最后已知状态，不构成签名许可 |
| 模拟或演示 | 机制的本地示例 |

未来发布时，请核查公布的可用性及提供给用户的模块地址。

## 重做核查

检查代币、hook 与池的身份，再检查注册表现行模块及其 `moduleRevision`。将事件与交易 hash 和规范区块对应。

Proof 页面可追踪税和买墙。截图或旧报告不能替代版本识别。[版本实际状态](../securite/etat.md)。
