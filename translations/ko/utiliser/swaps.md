# 매수와 매도

dapp은 선택한 배포의 라우터로 ETH/CUBIT 스왑을 제공합니다. 세금은 hook에서 적용되며 예상 수령액은 견적에 포함된 세금을 이미 뺀 순액이어야 합니다.

> Ethereum에 연결된 dapp은 **LP 수수료 0.01 %**인 현재 버전을 사용하며 그 버전의 ABI를 읽습니다. 시장이 열리기 전에는 교환이 불가능합니다. 데모나 시뮬레이션은 온체인 상태가 아닙니다.

## 스왑 준비 전

지갑 네트워크, 표시된 배포, 데이터 블록을 확인하세요. 교환액 외에 gas용 ETH도 준비하세요. dapp은 RPC 불가나 오래된 데이터를 알리고 검증되지 않은 상태에 기반한 서명을 막아야 합니다.

계정·네트워크·금액·라우터 주소가 바뀌면 새 견적이 필요합니다. 주변 주소는 V2 레지스트리로 변경될 수 있습니다.

## CUBIT 매수

1. ETH 금액을 선택합니다. exact-input이면 매수세 3 %가 이 금액에 포함됩니다.
2. 예상 순 CUBIT, 수수료, 슬리피지 허용치로 정한 최소 수령량을 읽습니다.
3. 시뮬레이션과 지갑 세부사항을 확인한 뒤 서명합니다.
4. 성공 영수증과 온체인 잔액 갱신을 기다립니다.

매수는 `msg.value`로 네이티브 ETH를 사용합니다. CUBIT 라우터의 이 경로는 Permit2를 쓰지 않습니다. 새 버전에서 매수는 밴드의 x·y=k 곡선을 따라 밴드에서 CUBIT을 꺼냅니다.

## CUBIT 매도

매도에는 라우터가 선택한 CUBIT 수량을 전송하도록 **ERC-20 승인(approval)**이 필요할 수 있습니다. 프런트엔드는 요청 수량만큼 승인을 준비합니다.

승인 확인 후 dapp은 스왑 전에 계정, 네트워크, 레지스트리 개정번호, 견적 최신성을 재확인합니다. 기존 허용량이 부족하면 승인과 매도는 별도 거래입니다.

매도는 15 % 세금을 뺀 ETH를 반환합니다. 총 ETH의 12 %는 매수벽 자금, 3 %는 팀 몫입니다. 새 버전에서는 매도가 자신이 완전히 통과한 매수벽을 비우고 대기 중인 ETH를 매수벽 하나에 배치합니다. 이어서 CUBIT 라우터가 흡수된 CUBIT을 vault 준비금으로 보냅니다.

## 최소 수령량과 마감 시간

**슬리피지**는 견적 대비 허용 편차를 제한합니다. 견적에 세금이 포함되었다고 슬리피지를 임의로 15%p 더해서는 안 됩니다.

확인한 프런트엔드 소스에서 견적 유효 시간은 **30초**입니다. 거래 마감은 체인 timestamp로 계산합니다. 승인 대기가 길면 이 검사로 서명이 차단될 수 있으며, 그때는 최신 견적을 다시 확인해야 합니다.

한도에 따른 거래 거절은 합의한 최소·최대 금액을 보호합니다. 실패했다고 한도를 없애야 하는 것은 아닙니다.

## 거래가 실패할 때

| 상황 | 필요한 조치 |
| --- | --- |
| 잘못된 네트워크 또는 계정 변경 | 원하는 맥락으로 복귀 후 새 견적 요청 |
| 견적 만료 | 순액과 최소 수령량 재계산 |
| 라우터 또는 개정번호 변경 | 현재 주소와 새 동작 확인, 기존 승인은 이전 spender에 유지 |
| 유동성 부족 | 더 작은 금액의 견적과 존재하는 포지션 확인 |
| 매우 많은 매수벽을 통과하는 매도 | 매도 분할. 통과하는 매수벽이 약 88개를 넘으면 거래 하나의 gas 한도를 초과함 |
| RPC 불가 | 유효한 온체인 읽기 후 서명 |
| 이미 전송한 거래 | 다음 거래 준비 전 hash와 영수증 확인 |

라우터는 완전히 소모하지 못한 입력과 완전히 제공하지 못한 exact-output을 거절합니다. 되돌린 거래의 지출은 gas를 제외하고 EVM이 취소합니다.

## 결과 확인

hash는 제출을 뜻하고 성공 여부는 영수증만 알려줍니다. 탐색기의 네트워크, 상태, 수신자, `BuyTaxed` 또는 `SellTaxed` 이벤트를 확인하세요.

매수벽 기준가는 개별 주문 견적을 대체하지 않습니다. [dapp 데이터 읽기](preuves.md).
