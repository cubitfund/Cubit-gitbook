# dapp 데이터 읽기

Proof 페이지는 표시 수치를 프로토콜 상태·이벤트와 대조합니다. 금액 해석 전에 **네트워크, 배포, 버전, 읽기 블록**부터 확인하세요.

> 공개 dapp은 운영 중인 Ethereum 배포와 그 ABI를 읽습니다. 아래 데이터는 인터페이스가 구분해야 할 항목을 설명합니다.

## 구분해야 할 수치

| 데이터 | 설명 |
| --- | --- |
| 시장 가격 | 특정 수량의 순결과와 다른 현재 풀 가격 |
| 밴드 ETH | 현재 가격에서 밴드가 실제로 보유한 ETH, 매수자가 넣은 자금 |
| 밴드 CUBIT | 밴드가 아직 매수용으로 제공하는 CUBIT |
| 다음 매수벽 목표 | 현재 가격으로 계산한 가격대, 자금을 조달한 포지션과 별개 |
| 유효 매수벽 | 이미 자금을 조달한 포지션별 ID, tick, 잔여 유동성 |
| 대기 ETH | 배치되지 않고 남은 매수벽 자금: 포지션을 만들기에 너무 작은 미세 잔량, 또는 tick 범위의 맨 위에 있는 가격 |
| 전송 대기 CUBIT | 통과된 매수벽의 CUBIT, vault로 전송될 때까지 hook 안에 격리됨 |
| 보상 준비금 | 예치자에게 지급하려고 vault가 보유한 CUBIT, 예치금과 별개 |
| 유통 공급량 | 총공급량에서 매수벽의 CUBIT, 전송 대기 중인 CUBIT, vault들의 보상 준비금을 뺀 양이며, vault에 예치된 CUBIT은 유통량에 남음 |

매수벽 가격대와 잔여 ETH를 함께 읽어야 합니다. 밴드 ETH와 매수벽 ETH는 서로 다른 두 장부에 속합니다.

## 새 버전에서 달라지는 점

이전 뷰는 래더, 쿠션, 소각 대기열, 유지보수 화면을 표시했습니다. 새 버전은 이를 단일 밴드, 매도마다 배치되고 비워지는 매수벽, vault의 보상 준비금으로 대체합니다. Keepers 페이지는 더 이상 없습니다.

과거 이름 `floorPrice`는 가장 최근에 자금을 조달한 매수벽을 나타내며, 시장 전체 최저가로 읽으면 안 됩니다. 가격이 내려가면 새 매수벽이 이전 매수벽보다 낮게 배치될 수 있습니다.

새 필드는 [통합](../developper/integration.md)에 설명합니다. Ethereum에 연결된 dapp은 현재 버전의 필드를 읽습니다.

## 총가격·순가격·견적

총기준가는 포지션 가격대를 뜻합니다. 순기준가는 구간 경계, LP 수수료, 매도세, v4 프로토콜 수수료 가정을 포함할 수 있습니다.

실제 매도는 수량, 통과 포지션, 반올림, gas에 달려 있습니다. “net floor”는 지갑 성과 계산이 아니며 견적을 대체하지 않습니다.

## 데이터 모드

| 표시 | 해석 |
| --- | --- |
| 온체인, 블록 식별됨 | 표시된 배포에서 읽은 데이터 |
| 로딩 중 | 첫 읽기 미완료 |
| 오래된 데이터 또는 RPC 장애 | 마지막 알려진 상태이며 서명 허용 근거 아님 |
| 시뮬레이션 또는 데모 | 메커니즘의 로컬 예시 |

향후 릴리스는 공지된 이용 가능 여부와 사용자에게 제공하는 모듈 주소를 확인하세요.

## 다시 검증하기

토큰·hook·풀 식별자를 확인하고 레지스트리의 현재 모듈과 `moduleRevision`을 확인합니다. 이벤트를 거래 hash 및 정규 블록과 대조합니다.

Proof 페이지에서 세금과 매수벽을 추적할 수 있습니다. 스크린샷이나 옛 보고서는 버전 식별을 대체하지 않습니다. [실제 버전 상태](../securite/etat.md).
